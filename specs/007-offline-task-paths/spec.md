## User Scenarios & Testing *(mandatory)*

### User Story 1 - 一次提供明示的品牌资料 (Priority: P1)
用户提交带有明确字段标签的完整句子，资料草稿应填入对应名称、介绍、风格；有明确定位才填写定位。用户核对确认后才成为品牌事实。

**Independent Test**: 输入“我要建立一个测试品牌。品牌名称：验收测试茶铺1122；品牌介绍：一家面向大学生的单门店茶饮店，主要提供自提服务，表达风格自然、简洁。先不要生成营销文案，也不要创建促销活动。”；兼测“表达风格：自然、简洁”显式标签版本。

**Acceptance Scenarios**:
1. **Given** 一行包含多个明确标签且前有说明文字，**When** 创建草稿，**Then** 名称与介绍正确，风格明示时可提取；不重复要求已识别必填项。
2. **Given** 未明示品牌定位，**When** 展示草稿，**Then** 定位为空且不强制补齐，不臆测为已确认事实。
3. **Given** 无法确定边界或不支持的自由表达，**When** 无法可靠提取，**Then** 保留原文，说明离线识别限制并引导编辑资料卡，不把整段操作指令当字段。
4. 原有逐行资料和商品多规格关系保持；未确认草稿不得直接入库。

### User Story 2 - 只测算同单两杯的单位收益 (Priority: P1)
用户明确只看第二杯半价的单位收入、成本和贡献收益，不应被带到活动策划。

**Independent Test**: 已确认商品售价18元，输入“帮我检查桂花乌龙奶茶的第二杯半价：原价每杯18元，单杯变动成本8元，同一订单同款两杯，第二杯按原价半价，不叠加其他优惠。暂不设最低贡献标准，只展示两杯的收入、变动成本和贡献收益，不生成营销文案。”

**Acceptance Scenarios**:
1. 明确仅请求单位数值时进入单位检查，不强制日期、平台、预算、推广支出、销量或经营汇总。
2. 两杯收入27元、变动成本16元、贡献收益11元，平均每杯5.5元；不称为净利润，不声称达标。
3. 缺成本时仅追问必要缺项；“单杯变动成本：8元。”、“单杯成本8元”、“每杯成本：8元”及当前成本问题下的“8元”均可接续。
4. 同名不同规格不能误选；价格矛盾不得静默改商品事实；没有只看单位收益意图的活动策划保持原有路径和批准门禁。

### User Story 3 - 只改标题并诚实说明结果 (Priority: P1)
已有普通文案后，用户要求标题改为具体文字、正文不变，离线模式应按明确指令执行，保留历史版本。

**Independent Test**: “只把标题改成‘桂花遇见乌龙，日常一杯茶’。正文保持不变，不新增价格、优惠或商品特点。”

**Acceptance Scenarios**:
1. 新版标题与指定内容一致，正文、摘要、标签及交易条款保持不变，复制与历史记录呈现同一新版。
2. 能执行的改动才新增版本并提示成功；原标题相同则说明无需修改，不增加空版本。
3. 离线不支持或无法确定目标的改写，明确说明限制，不用未变化结果冒充成功；带交易条件变动的指令继续走既有校验。

### User Story 4 - 区分一次性操作与可复用风格 (Priority: P2)
具体标题和“正文不变”等本次操作不成为长期表达偏好候选。

**Acceptance Scenarios**:
1. 上述具体标题指令不覆盖当前可复用风格，不出现以整句操作指令为内容的新长期偏好候选。
2. 明确的“语气自然、简洁”等风格可用于本任务，保存为长期偏好仍需要用户明确确认。
3. 本轮没有用户点击保存的证据，不将已有记忆记录为被污染，不删除或批量修改历史记忆。

### Edge Cases
- 一行/多行资料，中文/英文冒号，分号、逗号、句号，说明前缀，缺字段、重复矛盾标签。
- 一次同时提供商品与成本；切换任务、成本追问后补答；包含否定要求如“不创建促销活动”。
- 成本零值须区分未知；负数、超过精度或含糊数字不得错误识别为有效金额。
- 指定标题中带标点或风格词，不能仅因词面“温柔/标题”就写为偏好。
- 无已有作品要求改标题、相同标题、超出离线支持范围、交易/功效限制和归档一致性。

## Requirements *(mandatory)*

### Functional Requirements
- **FR-001**: 离线提取明示的品牌必填信息，保留可追溯原文；未提供信息不补造，资料仍需确认。
- **FR-002**: 明确只求单位数值的请求进入独立单位优惠检查，不收集活动专属依赖。
- **FR-003**: 页面字段名称及常见分隔符可用于成本补答，金额保留既有人民币分口径与校验。
- **FR-004**: 精确标题替换遵守范围，正文等未请求字段保持；真实变化才新增版本，失败或无变化如实提示。
- **FR-005**: 一次性编辑与可复用风格分开，不能自动写长期记忆，也不把未保存候选记为已污染。
- **FR-006**: 明确标识离线能力和手工处理办法，不承诺完整自然语言理解；真实模式未测不能记为通过。
- **FR-007**: 不改变优惠公式、策略批准、权限隔离、供应商配置或历史事实，不新增海报功能与依赖。

### Key Entities
- 资料草稿及原文：已提取字段、未知字段、缺项和确认状态。
- 当前任务：单位检查或活动/文案路径及必要输入。
- 一次性编辑：目标标题与修改范围，可复用风格另行保存于当前任务。
- 文案版本：实际改动、父版本、复制及历史归档结果。
- 长期偏好：明确保存的可复用表达，与任务编辑分离。

## Success Criteria *(mandatory)*
- **SC-001**: 明示字段样例不再重复要求品牌名称与介绍；原有逐行样例仍通过。
- **SC-002**: 指定单位检查样例不追问任何活动专属字段，数值为27/16/11元，不生成文案。
- **SC-003**: 四类成本表述均完成同一补答；非法或含糊金额保持未知并解释。
- **SC-004**: 指定标题替换后正文逐字不变；同标题或未能执行不新增虚假成功版本。
- **SC-005**: 编辑指令不出现在新长期偏好候选中，未点击确认不新增长期记忆。
- **SC-006**: 全部原有检查及本轮回归通过；人工验收、自动测试、未验证真实模式分别记录。

## Assumptions and Dependencies
用户给出的五项是本轮明确范围，按既有需求修复，不增加品牌营销或图片生产。未提供定位可以为空；只求数值时不判断最低贡献达标。真实模型行为与第三轮一般UI改进后置。用户希望每轮一次方向确认；本轮将整份规格及实现方向一起评审，确认后才生成任务并实施，完成后仍停在本地人工验收。
