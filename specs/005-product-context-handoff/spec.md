## User Scenarios & Testing *(mandatory)*

### User Story 1 - 带着所选商品开始对话 (Priority: P1)

用户在当前品牌产品库选择一款商品，点击“开始营销创作”，进入该品牌的新对话。用户能看到本次商品名称和规格，后续发送需求时保持商品关联，不重复选择商品。

**Why this priority**: 当前选择被静默丢弃，阻断从产品库到营销任务的主流程。
**Independent Test**: 使用测试品牌两款不同规格或名称的商品，选择其中一款进入对话并发送普通商品介绍需求；不用真实模型验证商品传递。

**Acceptance Scenarios**:
1. **Given** 当前品牌下选中一款在用商品，**When** 点击顶部创作入口，**Then** 新对话属于该品牌，清楚展示对应商品名称/规格，待发送需求包含相应商品上下文，不自动调用内容生成。
2. **Given** 商品已带入新对话，**When** 用户修改预填文字但没有明确要求切换或取消商品，**Then** 商品关联不因文字变化而丢失。
3. **Given** 带入的商品名称已知，**When** 发送普通文案需求，**Then** 不重复询问主推哪款商品，可追问尚未明确的平台。

### User Story 2 - 单商品入口与恢复一致 (Priority: P2)

商品卡片的“围绕此商品创作”遵守相同的商品关联和显示规则，刷新、导航返回后不丢失未发送的商品上下文。

**Why this priority**: 修顶部入口不能损坏原有单商品入口，也不能让关联仅在首次预填时有效。
**Independent Test**: 从商品卡片进入新对话，检查商品提示，编辑预填文字，刷新及切换导航后发送。

**Acceptance Scenarios**:
1. **Given** 从单商品卡片进入创作，**When** 用户查看并编辑待发送消息，**Then** 商品可辨认，消息不被自动发送。
2. **Given** 有未发送的商品创作需求，**When** 刷新或去管理页再返回同一对话，**Then** 商品关联与消息保留，不串到其他任务。

### User Story 3 - 空选择、多选择和异常边界 (Priority: P2)

用户能够理解当前入口支持范围；任何无法处理的选择均有明确反馈，不隐式选择其他商品。

**Why this priority**: 当前任务按单个SKU处理，修复不扩展成未确认的多商品任务。
**Independent Test**: 分别以零、一、多款选择及商品被归档的情况操作。

**Acceptance Scenarios**:
1. **Given** 未选择商品，**When** 点击顶部创作入口，**Then** 仍可开启该品牌的通用新对话，不擅自选择唯一或第一款商品。
2. **Given** 选择多款商品，**When** 点击顶部入口，**Then** 明确提示当前一次围绕一款商品创作，保留原选择，不创建虚假的多商品任务或静默丢弃选择。
3. **Given** 所选商品已归档、删除或不属于当前品牌，**When** 发起创作，**Then** 拒绝错误关联并提示重新选择，不回退为其他商品。

### Edge Cases

- 跨页选择后进入创作：按实际选择集合检查数量，不只读取当前页。
- 修改文字后刷新：不能只在文字与预填原文完全相同时才保留关联。
- 另一品牌或旧任务：本次新任务不覆盖已有对话的品牌或商品。
- 当前任务忙碌：沿用现有防重复规则，不创建重复对话。
- 用户明确取消/更换商品：旧商品不强行覆盖用户新意图，沿用现有明确修改流程。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 顶部创作入口必须消费当前有效选择，支持已确认范围内的单商品上下文传递。
- **FR-002**: 新对话必须明确展示本次商品名称与规格；不能用“品牌已建商品数量”替代本次选择提示。
- **FR-003**: 单商品和顶部入口使用一致的商品关联行为，保留预填但不自动发送。
- **FR-004**: 用户编辑预填文字不得无意清除商品关联；明确切换/取消按用户意图处理。
- **FR-005**: 导航与刷新保留待发送消息及其关联，不污染其他任务。
- **FR-006**: 零选择保持通用入口，多选择显示明确范围提示，不静默选取其中一款。
- **FR-007**: 关联只接受当前授权品牌下的有效商品，价格和卖点继续读取可信商品资料。
- **FR-008**: 修复不得自动生成文案、创建促销、保存长期偏好或改动商品事实。

### Key Entities

- 商品选择：当前品牌内选中的商品集合，可能跨页。
- 对话商品上下文：当前新任务关联的一款商品及可读提示，与待发送文字分别管理。
- 对话草稿：尚未发送的用户文字及所属任务；本规格只涵盖导航/刷新和上下文关联，发送失败恢复另列需求。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 顶部和卡片两类入口的单商品案例均能准确关联选中商品，名称和规格展示一致。
- **SC-002**: 编辑预填文字、刷新、导航返回三个场景中，未主动改变的商品关联均保持。
- **SC-003**: 零选择、多选择、无效商品及品牌隔离案例均不发生静默误选或串用。
- **SC-004**: 进入创作但尚未发送时，不产生内容生成调用或商品事实修改。

## Assumptions

- 现有单SKU Agent 能力为本次修复边界；多商品 Agent 编排不在本次范围。
- 使用已有品牌和商品服务及身份机制，不新增框架、模型能力或数据库事实字段需求。
- 离线验证可证明上下文传递，不代表自然语言模型理解质量已通过。
- 先取得用户规格确认，再进入方案；取得方案确认后实现，人工验收通过前不提交/推送/开PR。
