## User Scenarios & Testing *(mandatory)*

### User Story 1 - 发送失败后仍可继续编辑 (Priority: P1)

用户输入或由快捷入口预填消息，发送遇到本地异常、服务拒绝或网络问题时，不必重新输入文字或选择商品。

**Why this priority**: 当前在确认发送成功前清空草稿，直接损失用户输入。
**Independent Test**: 使用离线环境模拟发出请求前异常和服务拒绝，不调用真实模型。

**Acceptance Scenarios**:
1. **Given** 输入文字并关联商品，**When** 请求发出前发生异常，**Then** 完整文字与商品关联保留，显示失败，允许编辑和重试。
2. **Given** 用户填写问题补充并选择选项，**When** 服务明确拒绝本次提交，**Then** 保留文本和仍有效的选项，不重复追问或要求重填；过期问题提示重新核对。
3. **Given** 发送失败后尚未重新发送，**When** 同一标签页刷新或导航返回，**Then** 可恢复该对话的草稿和关联，不串到其他任务。

### User Story 2 - 区分接收成功和后续处理失败 (Priority: P1)

消息被服务器接收后，生成失败或状态查询失败不能被当作未发送并自动再次提交。

**Why this priority**: 单纯在所有异常中恢复并重发可能重复创建消息与模型任务。
**Independent Test**: 分别模拟提交返回运行编号后查询失败、运行失败、提交响应丢失。

**Acceptance Scenarios**:
1. **Given** 服务器已经返回有效运行标识，**When** 轮询失败，**Then** 保留运行关联并提示查询状态，不自动将消息当新请求重发。
2. **Given** 请求超时且是否被接收未知，**When** 恢复草稿，**Then** 显示接收状态待确认，不自动重发；后续通过已有记录核对或以同一操作标识安全重试。
3. **Given** 服务器已接收并正常完成，**When** 刷新，**Then** 旧草稿不会重新填回，不重复显示已发送内容。

### User Story 3 - 不覆盖新输入 (Priority: P2)

失败恢复、任务切换与页面状态更新不得覆盖用户较新的草稿。

**Why this priority**: 异步处理可能在用户编辑后返回，旧内容不能覆盖新内容。
**Independent Test**: 使用延迟失败响应检查恢复目标对话和草稿的新旧关系。

**Acceptance Scenarios**:
1. **Given** 存在更新的用户草稿，**When** 较旧发送结果回来，**Then** 保留新输入，旧失败内容仍可找回而非覆盖。
2. **Given** 操作属于对话A，**When** 处理失败或导航至其他页面，**Then** 只更新A的发送状态，不把草稿写到对话B。

### Edge Cases

- 快捷指令和商品预填没有触发手动输入事件，仍应受到发送草稿保护。
- UUID生成等本地错误发生在实际网络请求之前。
- 空输入不创建发送任务。
- 网络超时不能等同服务器未接收。
- 浏览器草稿存储不可用时不能无提示清空用户内容。
- 同一轮多次点击沿用现有忙碌限制。
- 容器消息请求成功但模型执行失败，用户仍能区分已发送与执行失败。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 在任何可能失败的发送操作前保护待发送文字、任务标识、有效问题选项及商品关联。
- **FR-002**: 未接收的发送失败应保留或恢复可编辑内容，错误说明清楚。
- **FR-003**: 提交被确认接收后清理该条待发送草稿，不因后续模型失败自动重发。
- **FR-004**: 接收状态不明时保留内容及操作标识，提示待核实；不能声称发送失败就一定未执行。
- **FR-005**: 恢复不得覆盖新输入或串对话，导航/刷新与既有草稿行为一致。
- **FR-006**: 重试保留同一逻辑操作的身份，已接收内容不重复创建；请求内容改变按新的操作处理。
- **FR-007**: 错误及等待恢复不显示成虚假的发送/生成成功。
- **FR-008**: 不更改商品事实、长期记忆、促销规则和线上部署配置。

### Key Entities

- 待发送草稿：用户文字、问题选项、商品上下文及所属对话。
- 发送尝试：操作标识、发送内容、目标版本、接收状态及可获得的运行标识。
- 已接收消息：服务器已确认接收的输入，与内容生成是否成功分开判断。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 本地异常、明确拒绝、网络失败测试中，未接收草稿的文字和商品关联均不丢失。
- **SC-002**: 已接收后轮询失败或运行失败不触发自动重复提交。
- **SC-003**: 导航、刷新、跨对话及旧响应返回测试均不发生草稿串用或新输入覆盖。
- **SC-004**: 成功发送后刷新不恢复已发送旧草稿；错误状态可辨认。

## Assumptions

- 使用既有服务接收与运行标识，不扩大为新的消息平台。
- 会话内草稿恢复不承诺关闭浏览器后仍保留，也不新增跨设备草稿同步。
- 只处理发送及恢复，不包含模型内容质量和商品入口传递修复。
- 不承诺供应商调用严格只计费一次；本地重复请求行为与外部计费分别记录。
- 按团队流程：规格确认后写方案，方案确认后实现，人工验收通过后才提交与合并。
