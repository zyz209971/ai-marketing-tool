# BrandPilot 当前产品需求与实现边界

更新：2026-11-18。供 PM、Agent 组、经营工具组与前端组共同维护。

## 1. 产品目标与主要入口

服务单品牌、单门店自提的茶饮营销。用户通过对话和上传提供资料，Agent 理解任务、整理草稿、批量追问必要信息、调用经营工具并生成内容。品牌与作品管理用于查看和维护结果。

新用户不自动使用模拟门店。无需先填写品牌表单；可上传 TXT、MD、CSV、文字型 PDF 或 DOCX，也可直接描述品牌。资料草稿经用户确认才成为品牌事实。已有品牌可直接选择，模拟门店须明确选择。

本轮不新增登录。继续本地开发；部署配置保留，暂不发布公网。

统一工作台首页 `/` 默认对话。左侧为与 Agent 对话、品牌资料、产品库、营销创作记录、对话记录；聊天右侧呈现当前品牌事实、快捷任务和近期记录。资料管理使用全部内容宽度。已发任务与未发聊天草稿在导航时保留；管理页浏览其他品牌不会改写当前对话品牌。从产品库发起新对话可携带选中商品。作品与聊天记录是两类数据，作品可返回对应任务。

## 2. 四条任务路径与完成标准

| 路径 | 必要输入 | 完成结果 | 不应额外追问 |
|---|---|---|---|
| 品牌建档 / 更新 | 品牌名称、介绍；若导入商品，还需商品名称和可核实卖点 | 用户核对、处理差异后入库 | 不要求先具备销量、成本或活动计划 |
| 普通文案 | 已确认品牌资料、平台；商品文案还需选定商品 | 文案生成、归档，可局部改写 | 不要求成本、ROI、日期或预算 |
| 单位优惠检查 | 商品价格、单杯变动成本、明确优惠；最低贡献标准或明确选择仅显示计算结果 | 展示贡献收益与约束判断 | 不要求平台、日期、营销预算、预测销量 |
| 活动策略与文案 | 商品、平台、活动期、预算；ROI 情景另需实际支出假设、销量假设、经营基线、优惠参与情景 | 测算 → 策略版本 → 用户明确确认 → 文案 → 多轮修改 | 不把预算当实际花费，不把历史销量当预测 |

未知字段保留为空，不能填成零。独立问题每批最多三项；可一次回答、多轮补充、暂停或换目标。只改表达可保留已批准条款；改价格、优惠、商品、日期等须重新校验并确认策略。

普通文案若加入实际优惠承诺，转入活动路径。品牌资料确认与策略批准是两种不同操作，模型不能替用户批准。

## 3. 信息类别与归属

| 信息类别 | 字段 / 含义 | 保存与使用规则 |
|---|---|---|
| 品牌资料 | 名称、介绍、定位、表达风格、品牌偏好 | 确认后长期保存；本次写作风格不会自动覆盖品牌 |
| 商品资料 | 名称、规格、售价、卖点、分类、图片关联、价格确认时间 | 名称与卖点是导入底线；价格可在测算前补齐；同名多规格必须消歧 |
| 资料证据 | 文件、版本、提取文本、用户补充、手工编辑、旧新差异、确认时间 | 原件保留；文件中的指令不作为系统指令；不能伪造逐字引用 |
| 经营事实 | 商品 ID、两期日期和净完成杯数、单杯变动成本、最低贡献、可选产能 | 通过确认的经营资料入库；日期含开始不含结束，两期等长不重叠 |
| 当前任务 | task_kind、主题、目标、受众、平台、风格、限制 | 保存到本次任务，不自动进入长期品牌记忆 |
| 活动假设 | 活动期、预算上限、实际支出假设、销量假设、优惠规则、参与组数 | 明确标为情景；修改后此前批准失效 |
| 执行与结果 | 问题批次、对话、工具输出、策略版本、批准记录、文案版本与来源 | 可恢复任务；文案同步至作品管理，回到原对话修改 |

金额接口使用整数人民币分，折扣用万分比。未提供价格确认时间的旧商品显示未记录，不补造历史时间。

## 4. 经营判断的统一口径

- 单杯变动成本主要包括食材、包材等；贡献收益不等于扣除房租、固定工资后的净利润。
- 单位优惠以同单同款两杯演示。第二杯优惠的活动测算必须给出参与组数，每组两杯；`2 × 组数 ≤ 总杯数`。
- 例：160 杯中 20 组参加第二杯半价，则 20 杯折价、140 杯原价，不能把全部 160 杯自动两两配对。
- 活动增量贡献 = 情景销售收入 − 变动成本 − 不促销基线贡献 − 额外营销支出；增量 ROI 再除以额外营销支出。支出为零不输出无穷 ROI。
- 无最低标准可先看单位数值，不能声称达标；活动方案批准仍需明确约束。缺销量或参与假设可暂时只看单位收益。
- 历史日均只作比较情景，不证明促销的因果收益，不实现 CTR/CVR 归因。

## 5. 技术分工与权威数据

前端负责聊天、问题选择、附件与差异确认、策略卡、作品展示。主 Agent 通过模型理解意图与字段，LangGraph 管理执行与等待恢复；规则代码决定必填依赖、工具白名单、价格计算、版本批准和写入条件。

品牌事实、资料、经营数据、作品和确认事件保存在业务数据库；本地为 SQLite。原件保存在私有文件目录。LangGraph checkpoint 单独保存等待与恢复状态。营销案例 RAG 只参考写作风格，品牌资料用于事实检索；二者不能混用。

工程协作以运行时导出的 `docs/agent-contracts.json` 为结构依据。工具组提供确定性计算与数据校验，不另外开发聊天调度器；前端不直接保存模型密钥。

## 6. 本轮后置与限制

- 多门店、自动发布、完整图片/视频生产、新登录与成员管理均不属于本轮。
- 任意 Excel 表头识别、同时处理多份待确认附件尚未实现。
- Agent 入口支持新旧字段差异逐项确认；旧管理页仍为人工选择产品、核对文件后保存，尚未统一为同一冲突交互。
- 模型仍可能遗漏字段、超时或生成不准确表达；代码校验不能代替内容审核。当前文案生成对数字与交易表述限制较严。
- PostgreSQL 配置已保留，但本机没有完成真实 PostgreSQL 与公网部署验证；课堂小规模使用仍需部署后验收。

任务路径规格见 `specs/003-brand-task-paths/`，工作台规格见 `specs/004-unified-workbench/`。数据字段、营销手段边界和逐步案例见 [数据准备指南](marketing-data-guide.md)。本文件描述需求与边界，实际验证结果另见本轮交付记录。
