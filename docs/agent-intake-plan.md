# 上传资料与对话补全实现记录

## 目标

模板保留为后台的数据规范，用户通过文件和聊天填写。文件已有字段不重复问；缺失信息不使用零或模型常识补齐；草稿需用户确认才进入品牌和经营资料。

## 实现流程

1. 空白对话直接上传 TXT、Markdown、CSV、文字 PDF 或 DOCX，无需先填写品牌创建表单。内部创建待完善工作空间，其占位信息不作为用户事实。
2. 保留不完整商品。品牌必填名称、介绍；发现的商品必填名称、明确单价、卖点。定位、风格、分类可选。已有品牌和同名唯一商品可以复用已确认字段。
3. 后端检查缺项，每轮默认问一项；模型结合正在询问的字段理解简短回答，也支持一次补多项。工具调用 `fill_intake` 返回字段路径、值和用户原文依据；后端再次验证路径、依据、金额与日期。
4. 草稿、补充记录、问题位置持久保存。缺项时禁用确认，直接调用 API 也无法绕过。补齐后显示可核对资料卡，用户确认后入库。
5. 经营 CSV 沿用既有字段模板，但缺少日期、销量、成本时可通过聊天补齐；明确的零保留，未知不当零。统计区间等长、不重叠，截止日不含。
6. 活动需要情景 ROI 而缺少经营基线时，生成对话经营草稿。补齐确认后恢复原活动文本、预算、平台等条件，继续测算。
7. 确认关键资料后使旧策略、缓存、文案失效；重新测算并要求确认。可取消待处理草稿，取消的内容不进入分析。

## 模块

| 模块 | 职责 |
|---|---|
| `organization.py` | 为 Agent 保留不完整提取结果；原管理入口保持严格模式 |
| `marketing_agent/intake.py` | 字段规范、缺项、追问、模型回答提取、草稿合并、确认门禁 |
| `marketing_agent/attachments.py` | 上传建档、预览、确认、取消、恢复原活动 |
| `marketing_agent/data.py` | 不完整经营草稿与完整记录的类型和校验 |
| `marketing_agent/graph.py` | 先处理补资料，再回到营销工具编排 |
| `marketing_agent/provider_errors.py` | 模型权限、额度、限流的明确提示，不返回原始请求或密钥 |
| `frontend/src/agent-workspace.js` | 上传入口、缺项摘要、预览、确认与取消 |

沿用 FastAPI、LangGraph、SQLAlchemy 和 OpenAI 兼容 SDK，没有增加子 Agent。上传、确认使用任务占用与 revision 防止并发覆盖；待处理资料存在时禁止确认活动策略。

主 Agent 每轮先通过独立的 `extract_brief` 调用提取用户需求，参数显式包含 Brief 的平台枚举、金额整数分、日期及优惠结构；随后 `decide_marketing_action` 只判断意图与选择工具，禁止改写已提取需求。两个步骤仍属于同一个主 Agent，不是新增子 Agent。格式错误各最多修复一次，修复前不会执行工具或写入事实。对于制定策略的意图，资料齐全后由后端强制形成待确认策略卡，模型单纯文字答复不能跳过确认。

## GLM 配置

在私有 `backend/.env.local` 中使用 `QWEN_BASE_URL=https://openrouter.ai/api/v1`、`COPY_MODEL=z-ai/glm-5.3-flash`、`USE_MOCK=false`，`WORD_API_KEY` 保留用户的 OpenRouter Key。三个 `AGENT_*` 留空即可复用。模型 ID 已核对 OpenRouter 模型目录，支持 tools / tool_choice；不需要另一套 GLM SDK。

此前 DeepSeek 被当前 Key 的工作空间 Guardrails 拒绝；按用户指定切换 GLM，没有修改账户权限规则。真实提取、发现缺项、自然语言补充与确认建档已通过；完整经营闭环使用下面的 live 脚本验证。

## 测试入口

- `backend/tests/test_marketing_agent.py`：上传建档、缺项追问、短回答、刷新恢复、未知值、非法日期、绕过确认、来源验证、恢复活动、取消、模型权限错误。
- `frontend/tests/agent-intake-browser.mjs`：空白对话上传不完整品牌资料，补齐，经营补充，确认并生成文案，检查移动端。
- `backend/scripts/smoke_intake_live.py`：使用真实本地密钥，在隔离的 `.local-data/intake-live-*` 数据库测试；默认2次模型调用，`--full` 继续验证经营工具与文案生成。会产生模型调用费用，不作为自动回归。

## 当前边界

- 同一对话一次处理一份待确认附件；确认或取消后再上传下一份。多附件冲突合并尚未实现。
- 经营上传仍使用原 CSV 表头，暂不支持任意 Excel 表头自动映射。品牌文档里的成本和销量不会自动转换成经营表，需要经营 CSV 或后续对话补充。
- 图片、扫描件依赖另行配置的视觉模型，本轮使用文字文件验证。
- 文档确认和任务状态跨多次数据库写入，不承诺分布式事务；服务中断后检查记录再重试，不自动重放模型调用。
- 测试数据均为虚构，功能测试不证明实际营销收益。
