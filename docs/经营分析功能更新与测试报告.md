## 1. 更新概览

本次实现了以下最小完整业务闭环：

```text
团队 CSV
  → 上传及字段校验
  → 数据预览
  → 用户确认入库
  → 品牌隔离与幂等去重
  → 统一经营指标计算
  → 看板与 Agent 共用结果
  → 绑定已批准活动版本
  → 活动订单模拟及 CSV 回传
  → 历史基线 / 活动预期 / 实际结果复盘
```

金额在数据库和 API 中统一使用人民币整数分，避免浮点误差；日期区间统一采用 `[start, end)`。真实数据与合成数据通过 `synthetic` 字段区分。

## 3. 数据导入实现

### 3.1 支持的数据

- `产品知识库.csv`：产品价格、卖点和分类的唯一权威来源；
- 经营 `products.csv`：导入时只使用商品编号、名称和规格，价格、卖点和分类不会进入经营 SKU 表；
- `costs.csv`：商品的成本生效日期及原料、包材、其他变动成本；
- `orders.csv`：订单日期、商品、数量、原价、优惠、退款及活动编号；
- `campaign_feedback/orders.csv`：团队提供的历史活动回传数据；
- 标准英文订单 CSV：供活动模拟器和其他系统回传使用。

导入顺序为：

```text
products.csv → costs.csv → orders.csv → campaign_feedback/orders.csv
```

### 3.2 预览、确认和幂等

```http
POST /api/operations/imports/preview
POST /api/operations/imports/{import_id}/confirm
```

预览阶段完成表头、字段类型、日期、金额、商品归属和文件内重复校验。确认阶段才写入数据库。

订单唯一键：

```text
workspace_id + brand_id + order_id + line_id
```

相同数据再次导入时返回 `duplicate_count`，不会重复写入，也不会造成经营统计翻倍。

### 3.3 缺失值处理

- 缺失金额不会无条件填零；
- 未知金额保存为 `null`；
- 汇总结果同时返回 `incomplete_fields`；
- 依赖缺失金额的收入或贡献结果返回 `null`，避免产生虚假指标。

## 4. 数据库结构

| 表 | 用途 | 关键字段 |
|---|---|---|
| `ops_import_batches` | 保存导入预览、确认状态和错误记录 | 工作空间、品牌、文件哈希、数据类型 |
| `ops_skus` | 经营 SKU 映射 | 品牌、商品编号、名称、规格、来源、合成标识；不保存价格和卖点 |
| `ops_costs` | 商品有效期成本 | 商品编号、生效日期、成本分项、总成本 |
| `ops_orders` | 订单级经营事实 | 订单、商品、金额、费用、活动版本、来源 |
| `ops_campaigns` | 固化已批准活动版本 | 任务、策略、版本、优惠、预期、基线 |
| `ops_simulations` | 保存模拟运行和订单结果 | 场景、种子、活动版本、费用、订单 JSON |

所有经营数据查询同时限定 `workspace_id` 和 `brand_id`。

## 5. 经营计算与接口

### 5.1 五类经营能力

| 能力 | 接口 |
|---|---|
| 经营指标汇总 | `GET /api/operations/brands/{brand_id}/summary` |
| 日、周、月趋势 | `GET /api/operations/brands/{brand_id}/trends` |
| 商品经营分析 | `GET /api/operations/brands/{brand_id}/products` |
| 活动收益测算 | `POST /api/operations/campaigns/estimate` |
| 活动结果复盘 | `GET /api/operations/campaigns/{campaign_id}/review` |

另提供看板统一数据源：

```http
GET /api/operations/brands/{brand_id}/dashboard
```

该接口一次返回 `summary`、`trends` 和 `products`。看板不需要再次计算金额。Agent 的 `get_sales_summary` 在存在订单数据时使用同一计算模块；不存在订单数据时仍使用原有汇总数据，保持向后兼容。

### 5.2 主要计算口径

```text
GMV = Σ 商品原价金额
营业收入 = Σ 客户支付 + Σ 平台补贴 - Σ 退款
商品成本 = Σ 单位变动成本 × 销量
商品贡献 = 营业收入 - 商品成本
贡献率 = 商品贡献 ÷ 营业收入
扣费后贡献 = 商品贡献 - 营销宣传费用
相对基线增量 = 当前扣费后贡献 - 历史基线贡献
```

## 6. 活动审批、模拟与复盘

### 6.1 审批版本绑定

```http
POST /api/operations/campaigns/from-approved-strategy
```

创建活动前会校验：

- Agent 任务属于当前工作空间；
- 策略 ID 和版本一致；
- 策略状态为已批准；
- 审批记录存在；
- 策略依赖摘要没有因参数变化而失效；
- 优惠方案没有触发负贡献风险。

优惠参数发生变化后，模拟请求返回 `409`，要求重新审批。

### 6.2 高成本风险校验

```http
POST /api/operations/campaigns/risk-check
```

验收案例：售价 18 元、单位成本 15 元、第二杯半价。

```text
两杯收入 = 18 + 9 = 27 元
两杯成本 = 15 × 2 = 30 元
每组商品贡献 = 27 - 30 = -3 元
```

接口返回：

```json
{
  "blocked": true,
  "pair_revenue_minor": 2700,
  "pair_cost_minor": 3000,
  "pair_contribution_minor": -300
}
```

### 6.3 四种模拟场景

```http
POST /api/operations/campaigns/{campaign_id}/simulate
```

| 场景 | 处理方式 |
|---|---|
| `stable` | 预期销量在活动日期内基本均匀分配 |
| `declining_sales` | 按逐日下降权重分配销量 |
| `high_cost` | 提高订单单位成本以模拟负贡献风险 |
| `underperforming` | 默认实际销量为预期销量的 60% |

相同输入和随机种子会产生相同业务分布。每次运行返回 `simulation_run_id`、活动版本、数据来源、`synthetic=true` 和 CSV 下载地址。

### 6.4 复盘结果

复盘明确区分：

- `baseline`：历史基线；
- `expected`：活动计划；
- `actual`：实际回传；
- `actual_vs_expected`：实际与预期差异。

接口返回 `causal_claim=false`，明确该结果是描述性比较，不是严格因果评估。

## 7. 验收案例计算结果

所有结果均从订单、商品成本、优惠参数和宣传费用计算产生，没有硬编码最终汇总值。

| 指标 | 历史基线 | 活动预期 | 实际回传 |
|---|---:|---:|---:|
| 销量 | 20 | 40 | 24 |
| 收入（分） | 36000 | 63000 | 32400 |
| 商品成本（分） | 13000 | 26000 | 15600 |
| 商品贡献（分） | 23000 | 37000 | 16800 |
| 宣传费用（分） | 0 | 10000 | 10000 |
| 扣费后贡献（分） | 23000 | 27000 | 6800 |
| 相对基线增量（分） | 0 | +4000 | -16200 |

生成的结构化结论：

> 活动销量相比历史基线有所增加，但营销优惠和宣传成本导致经营贡献下降。
