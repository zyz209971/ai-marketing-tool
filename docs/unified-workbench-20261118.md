# 统一营销工作台交付说明

日期：2026-11-18。对应 `specs/004-unified-workbench/`。

## 本轮改动

- `/` 改为默认 Agent 对话；左导航统一品牌资料、产品库、营销创作记录、对话记录。
- 按参考图采用暖白底、浅杏卡片、橙棕强调色、线性图标和三栏布局。管理页使用全部内容宽度；手机侧栏与品牌上下文可折叠。
- 右侧使用已确认品牌、产品数量、真实任务状态和近期记录。新品牌展示上传引导，不预置虚构资料；模拟门店仍需主动选择。
- 输入草稿、待答问题和运行中的任务保留在同一控制器。执行期间可查看管理页；后台完成不会把页面强制切回聊天。
- 全局品牌选择与任务品牌分开：浏览另一个品牌不改写已有对话；从商品卡片发起新对话，原预填内容提交时携带该商品 ID，若用户改写需求则交由 Agent 重新判断。
- 新作品归档后回到原对话修改；旧作品仍可查看编辑。对话记录有关键词、品牌、分页过滤。原 `agent.html?task=...` 自动跳转。
- 品牌、产品和旧作品管理复用原有逻辑。管理页自身的草稿/任务操作收进“品牌偏好与历史管理任务”，避免与聊天记录混淆。

## 技术实现与文件

沿用原生 JavaScript + FastAPI + 现有 LangGraph，没有另建前端项目或替换 Agent 后端。

| 文件 | 作用 |
|---|---|
| frontend/index.html | 唯一工作台框架与原有对话/上传对话框 |
| frontend/src/workbench.js / router.js | Hash 路由、共享品牌状态、上下文与会话记录 |
| frontend/src/workbench.css / icons.js | 本轮统一视觉与响应式 |
| frontend/src/agent.js | 导出初始化、打开、新建、预填；任务状态事件；聊天草稿 |
| frontend/src/app.js / management.css | 管理功能容器适配及样式隔离 |
| backend/app/marketing_agent/api.py / store.py | 会话摘要、品牌与关键词筛选、分页，保持工作空间授权 |
| docs/marketing-data-guide.md | 全流程字段、职责、营销方式边界与测试步骤 |
| docs/examples/marketing-case/ | 两份虚构品牌资料、经营字段值、六个计算情景 |

已提交任务由后端保存，未发文字在浏览器 sessionStorage。路由与任务执行解耦；更新管理页不会重建聊天控制器。管理页修改表单仍需保存后再离开，不声称所有未保存表单都有自动恢复。

## 数据准备的下一步

先收集一个获准使用的奶茶品牌、2–3 款商品、两期同口径销量、成本和最低贡献标准。先确定字段与计算口径，再搜集更多数据。

按数据指南从不完整上传开始验收，不直接灌入完整表绕开补问。普通文案不强制经营数据；成本检查不强制 ROI；活动 ROI 需显式销量、支出和优惠参与假设。样例为虚构数字，不能当真实门店建议。

当前优惠计算支持原价、每杯统一折扣、同款第二杯优惠。满减/券/套餐/会员需新增数据契约和确定性工具后再接入，不能仅靠提示词声称算过。
