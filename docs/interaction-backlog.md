### [P1] @Codex BUG-01 线上发送消息报错，阻断对话
- **环境/现象**：线上HTTP地址登录后发送品牌建档资料报 crypto.randomUUID is not a function，强制刷新仍复现。
- **期望**：当前部署访问方式下可以正常发送；缺少浏览器UUID能力不能阻断对话。
- **核查**：main 的 e8478e64f914adc5ba6b75de8cc3b127d879f38f 已包含兼容修复，本地保留该修复。2026-11-23对线上公开 /src/agent.js 进行普通及带随机查询参数的无缓存只读请求，均仍得到 const key=()=>crypto.randomUUID();；该文件字节与 e8478e6 前一版完全相同，与修复版不同。不是仅凭用户浏览器旧缓存推断。
- **证据**：线上agent.js SHA256为 4ee7f0a92de5a497d4f0fb4fc8332bcc983045f33a7c174946a36a4f6a7f31a7；ETag为336782ae7565ebdb90c8ac5859f21f51。完整只读记录保存于本地忽略目录 .local-data/bug01-online-check.json。app.js及services/api.js的UUID调用均已有兼容处理。
- **回归**：新增 frontend/tests/uuid-compat.test.mjs，覆盖三个入口crypto缺失、randomUUID缺失、原生能力可用；6项通过。旧agent.js在同条件下可复现原错误。当前前端全部32项通过。
- **Owner待办**：核对实际运行镜像/源码版本，以及静态文件挂载、服务路由和服务端缓存；按发布流程部署包含修复的版本，再核对线上返回文件并登录实测发送。只读文件证据不能确认整套生产提交号。本轮未登录线上账号、未发送线上消息、未部署。
- **状态**：本地兼容处理及回归通过；线上仍提供旧agent.js，未解决。待Owner处理后再线上验收。第一轮范围含BUG-01、BUG-02、BUG-03，离线识别及提问界面优化后续分别处理。

## 使用说明

1. 新问题放对应优先级分区**最上方**，用下面的模板；
2. 标题格式：`[P1/P2/P3] 一句话标题`，认领后加 `@名字`；
3. 开发按《团队开发指南》第二节回路走：本条目 → Spec Kit 建 spec → 改 → PR（PR 描述里引用本条目）；
4. 合并后回来把标题改成 `[x] 已解决（PR #N）`，正文保留作历史。
