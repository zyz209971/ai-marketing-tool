# 营销 Agent 本地开发说明

当前为 2026-11-15 整合版：品牌资料确认、单门店经营 CSV、对话补资料、优惠备选、策略版本确认、文案生成与局部修改。可选显式模拟门店，或用户确认的品牌经营数据。默认复用文字模型配置；没有密钥或明确离线时使用标注的规则演示。尚未验证真实模型调用，未对外发布。最新操作步骤和边界见 [整合验收说明](agent-integration-guide.md)。

## 启动

在项目根目录运行 PowerShell：

```powershell
./start-agent.ps1
```

打开 <http://127.0.0.1:8021/agent.html>；原有后台入口 <http://127.0.0.1:8021/>。

新电脑第一次需要：

```powershell
python -m venv .venv
./.venv/Scripts/python.exe -m pip install -r backend/requirements-agent.txt
```

运行数据在 `.local-data/agent/`，不覆盖其他工作区数据库。服务仅监听本机地址，并且 Agent API 单独拒绝非本机或代理请求。此限制不能替代未来公网版本的登录与租户授权。

实时模型：在 `backend/.env.local` 或已有 `backend/.env` 中配置 `WORD_API_KEY`（或 `QWEN_API_KEY`）、`QWEN_BASE_URL`、`COPY_MODEL`。也支持 `-EnvFile` 指定仓库之外的私有文件，`-Check` 只检查配置，不发起调用。默认自动检测配置；`-Live` 强制实时，`-Offline` 强制离线。详见 [密钥配置与提交](model-configuration.md)。当前 SDK 调用 OpenAI 兼容的 function/tool calling；模型不支持或返回不合法结构时会明确失败，不会静默切换为规则演示。模型模式与经营数据来源独立：所选品牌决定使用示例或用户提供的数据。

## 基线

本地分支 `feat/marketing-agent` 基于 `origin/main` 的 `ec0c366`，合并共享工作空间 `610b669`。保留主分支的 Embedding 批量上限修复和 `frontend-v2` 设计稿；实际服务继续托管 `frontend/`。原先两个 worktree 未改写；本次新功能位于当前 worktree。未推送远端。

## 已实现

- FastAPI 接口、后台线程执行、请求回执、轮询与刷新恢复。
- Pydantic 严格校验字段；信息逐轮合并，显式 `null` 清除字段，未知字段拒绝。
- LangGraph 意图节点、受控工具选择、工具结果回传、固定校验节点和生成节点。
- 模型每轮最多有限次选择工具；相同工具结果在需求未变化时复用。
- SQLite LangGraph 检查点；SQLAlchemy 业务记录使用已有工作空间数据库引擎。
- 此版本在等待用户时结束图运行并保存业务阶段；下一条消息从理解节点开始。没有使用 `interrupt()/Command` 自动恢复半个节点，避免外部生成重复执行。重启时未完成请求标记失败，用户检查后再提交。
- 三个模拟分析工具，计算过程是真实 Python 算术；三款商品、28 天完整模拟订单、同单配对、分级舍入、单位收益约束、ROI 情景和候选折扣敏感性比较。
- 策略与文案版本，后端确认门槛；关键字段变更使旧确认失效，旧文案标记历史。
- 文案复用现有模型 provider；内部成本与销量不进入文案提示词。交易条件由代码渲染固定，生成模型仅写非交易性开场；不宣称语义审查已完全自动化。
- 对话优先的桌面与窄屏界面；每轮逐项追问，支持简短回答和建议回复。策略及作品卡片嵌入对话，测算细节默认折叠，不展示长表单或原始调试JSON。

## 数据和计算边界

固定门店 `demo-store`，交易渠道自提，推广平台支持小红书、抖音、公众号。T001/T002/T003 模拟标价为 16/18/20 元，成本为 6/6.5/7.5 元，最低平均贡献为 5 元，单日容量 200 杯，渠道费明确设零。固定样本期为 2026-10-19 至 2026-11-15，数据完整且无退款/补贴。

模拟样本从 `business.records()` 生成，`/api/agent/demo-orders` 可以读取。绑定品牌后的商品、价格、知识和风格读取原品牌管理服务；经营 CSV 以产品 ID 显式关联。缺失成本、最低贡献不采用模拟默认值。活动可在缺少历史基线时完成单位测算，但不输出增量 ROI。以上三款模拟商品参数仅适用于未绑定品牌的演示。

所有金额为整数分、日期区间含开始不含结束、折扣为支付原价的基点，按单杯实际折后价四舍五入到分。第二杯折扣固定为同SKU同规格、同单、每两杯重复配对、不叠加。情景假设全部购买尽量配对，奇数余杯原价；真实订单配对分布不同时不能直接套用这个情景总收入。

贡献收益 = 商家收入 - 变动成本。不包括房租、固定工资及真实税务结算，因此不是净利润。

增量贡献净额 = 活动情景贡献 - 不做活动情景贡献 - 新增营销支出。

情景增量 ROI = 增量贡献净额 / 新增营销支出；分母为零返回 null。基线为最近14天日均销量 × 活动天数，假定原价销售，不是因果估计。候选折扣使用相同销量，只能比较敏感性，不是价格最优化。预算上限不等于预计支出；缺少销量情景时询问，或由用户选择只判断单位收益。

## 交互与验证案例

1. 新建活动，输入「茉莉鲜奶茶，小红书，第二杯半价，预算200元」。应询问日期、实际支出、销量假设，不能生成。
2. 补充「2026-11-16 到 2026-11-23（不含），预计花费200元，预计销量160杯」。应得到策略v1、单位贡献6元、基线98杯、增量贡献-220元、情景ROI -110%。负ROI为风险提示，不等于单位收益不可行；用户仍可在了解风险后确认。
3. 点击策略确认，生成文案。用户文字「好的」不会替代后端确认动作。
4. 输入「标题活泼一点」，只改表达，活动条款保持不变。
5. 输入「好的，不过第二杯改成七折」，创建策略v2并重新确认，旧作品标记历史。
6. 输入「单杯成本10元」，第二杯半价应违反最低单位贡献约束；不能进入确认。
7. 选择「只看单位收益」，可以不提供销量假设及营销支出；文案仍需商品、平台、活动时间、预算上限和优惠。
8. 刷新页面保留任务；同一请求标识重复发送返回同一执行记录。相同标识不同内容返回409。每个任务同时最多一个执行。

离线规则解析只覆盖有限表达与追问场景，不能用于评价自然语言理解质量；完整自然语言交互需要配置真实模型后验证。

## 工具组交付规范

查看 `docs/agent-contracts.json` 或运行时 `/api/agent/contracts`，输入输出样例见 `docs/agent-tool-examples.json`。用 `python backend/scripts/export_agent_contracts.py` 从当前实现重新导出。外层统一 `schema_version/request_id/status/data_kind/snapshot_id/data_version/method_version/as_of/result/missing_fields/assumptions/warnings/source_refs/error`，result 按工具类型校验。

`brand_id=null` 使用示例商品；绑定品牌时 SKU 必须属于该品牌。当前每品牌只支持一个自提门店数据包，`store_id` 为兼容旧请求保留的占位字段，尚不提供多门店路由。外层 `status=ok/needs_data/error`；不可行是 `status=ok` 且 `result.feasible=false`。远端经营系统适配与授权仍需后续实现。

工具组只需要交付三项函数或其HTTP适配器：销售汇总、成本约束、优惠测算。Agent 侧负责聊天、任务和策略，不另建工具组聊天调度器。先增加数据源适配器，不能直接把真实数据混入固定模拟常量。
