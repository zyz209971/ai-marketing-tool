# 整合版操作与验收说明

2026-11-18 更新：优先参考 [四路径体验步骤](brand-task-paths-20261118.md) 与 [当前产品需求](product-requirements.md)。普通文案不要求经营数据；单位优惠检查不要求活动日期或预算；第二杯活动测算必须明确参与组数。

## 启动与入口

在项目根目录运行 `./start-agent.ps1`。打开 http://127.0.0.1:8021/agent.html 。原品牌管理入口仍为 http://127.0.0.1:8021/ 。队友原版只读对照运行在 8022，没有合并覆盖其源码。

首次使用可以直接点击「添加资料」上传品牌文件，不必先填写品牌表单。也可在左侧选择已有品牌。已有品牌来自当前启动配置的数据库；其他工作目录的数据不会自动搬入。

## 推荐体验：上传后在聊天中补齐

在空白对话上传 `docs/examples/brand-incomplete-demo.txt`。系统保留已知品牌名、商品名和18元售价，询问缺失的品牌介绍或卖点。按实际问题回答，例如“面向大学生的花香茶饮品牌”“桂花香气与鲜奶风味”。补齐后核对资料卡并确认，才进入品牌库。

经营 CSV 中缺失的成本、销量和日期也可通过聊天补充，例如单杯成本问答直接回复“6.5元”。ROI 缺少历史经营信息时，会生成对话草稿并逐项追问；确认后继续原活动任务。无需把同一个文件重新填好再上传。

当前一次处理一份待确认资料；任意 Excel 表头自动识别、多文件冲突合并尚未实现。完整设计与边界见 `agent-intake-plan.md`。

## 可选：使用完整资料快速体验

1. 新建一个测试品牌，填写名称和介绍。
2. 点「添加资料」→「品牌 / 商品资料」，上传 `docs/examples/brand-demo.txt`。此文件清楚标为虚构示例。修改预览中的名称、售价、卖点后确认。草稿不能直接进入分析。
3. 点「添加资料」→「经营汇总 CSV」→下载当前品牌模板。模板使用真实产品 ID，不能用其他品牌 ID，也不能自行猜 ID。
4. 填写后上传。预览中核对统计期、销量、单杯成本与最低贡献，点击确认。本品牌旧经营汇总会被这一批替换。
5. 发送「桂花鲜奶茶，小红书，下周，预算200元，预计花费200元，预计销量160杯；如果采用第二杯优惠，假设20组参加，其余原价，帮我比较活动方案」。这些数字只是用于体验的假设，不代表真实业务。
6. 从备选卡中选择可行方案，再点击策略卡「这个方案可以，帮我写文案」。选择备选与授权生成是两个步骤。
7. 发送「只把标题改得活泼一点，正文不动」：新版本标题变化，正文和条款保持；发送「第二杯改成七折」则重新形成待确认策略（如果原本就是七折，条件不变）。
8. 刷新后仍有会话、确认记录和作品。新建同品牌任务会读取已确认资料；切换品牌必须新建对话。

## 经营表字段

UTF-8 CSV，最多500款商品，当前仅单门店自提。不填即未知，禁止用0替代未知；0元成本只有在确实为零时填写。截止日不含当天。

| 字段 | 单位及含义 | 演示填写 |
|---|---|---|
| product_id | 下载模板中的商品 ID | 保留模板值 |
| current_start / current_end | 本期起止 | 2026-11-02 / 2026-11-16 |
| previous_start / previous_end | 上期起止，必须同长度且不重叠 | 2026-10-19 / 2026-11-02 |
| current_qty / previous_qty | 两期净完成杯数，非订单数 | 140 / 200 |
| variable_cost_minor | 单杯食材、包材等变动成本，整数分 | 650 |
| min_contribution_minor | 最低平均单杯贡献，整数分 | 500 |
| daily_capacity | 日最大履约杯数 | 200 |

金额不是元；650分=6.50元。经营表目前不计算实际净销售额，因为聚合杯数不能还原退款、折扣和订单组合。ROI 是「当前销量假设」相对「本期平均销量延续且原价销售」的情景增量 ROI，不是活动因果收益。

## 对话补资料

离线模式可发送 `品牌定位：面向校园的花香茶饮` 或 `表达风格：温柔简洁`，系统生成草稿，核对后确认。实时模式由模型识别知识补充意图。结构化草稿的修改以确认内容入检索，原文件保留作依据；非结构化长文如有错误，可在原品牌管理中上传修订版。

仅品牌定位、风格改变也会使既有策略失效。商品切换会清掉上一商品的临时成本覆盖；对话中补充的成本只作用于本次活动，不擅自改品牌主数据。

## 代码分工与队友方案取舍

| 文件 | 作用 |
|---|---|
| `marketing_agent/data.py` | 品牌快照、经营 CSV 校验和来源版本 |
| `marketing_agent/attachments.py` | 附件预览、对话知识草稿及确认 |
| `marketing_agent/model.py` | 意图、工具决策、受限优惠提案与解释 |
| `marketing_agent/business.py` | 唯一的活动测算入口，品牌数据和示例适配器 |
| `marketing_agent/graph.py` | 顺序依赖、追问、策略与资料变更失效 |
| `marketing_agent/content.py` | 品牌事实与原文上下文、代码保护局部修改范围 |
| `marketing_agent/store.py` | 会话、回执、策略版本与确认记录 |
| `frontend/src/agent-workspace.js` | 品牌选择、附件预览与经营表下载 |

选择性吸收队友的聊天附件、分析卡片、备选比较和「模型建议—代码计算—模型解释」。不迁入关键词主调度、全局最后一轮记忆、硬编码默认商品和存在接口断裂的第二套计算器。统计不做未经验证的滞销归因。

真实模型可提出2—3个不同折扣方案，支持同款第二杯折扣、单杯折扣、原价；模型不能改预算、销量或成本。离线模式使用明确的三套备选模板。不可行方案不能选择，最终生成前仍重新计算和核对版本。

## 本阶段限制

- 已通过一个 GLM 真实完整用例，尚未完成大规模自然语言稳定性和文案质量评测。
- 不支持多门店、外卖费用明细、满减/套餐、视频、自动发布。海报继续使用原管理功能，尚未纳入策略确认闭环。
- 图片及扫描件依赖真实视觉模型；聊天上传仅接收文档。语音未迁入。
- 后端只允许本机访问；共享工作空间不具备生产多租户权限，不可直接开放公网。
- 确认覆盖当前品牌经营数据；并发版本变化会拒绝旧草稿。数据库与外部生成不是分布式事务，服务中断后应核对记录再重试，不宣称外部模型费用恰好一次。
- 资料中的提示词、收益保证和未经证实功效不能作为系统指令。现有文本规则并非完整语义审核，发布前仍需人工核对。
