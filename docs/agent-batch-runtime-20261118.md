本轮范围：继续本地开发，保留原暖色设计，完成部署配置，暂不发布公网。原规格001保留；当前增量按 `specs/002-batched-agent-runtime` 维护。

## 用户能看到的变化

1. 上传缺资料的品牌文件，一次列出最多3个独立问题。可勾选选项集中提交，也能在同一个对话输入框一句话补充多项；只答部分也可继续。
2. 不知道、问原因、暂停补资料或切换营销目标，都作为对话意图处理。暂停的草稿保留，恢复后继续；未确认内容不会用于分析。
3. 先聊天后上传仍在同一个任务中，保留平台、预算等已表达条件，清掉模拟商品和模拟成本。确认真实资料后继续原目标。
4. 附件编辑有“保存编辑并检查缺项”，保存与确认分开。旧的已确认资料折叠显示。
5. 文案卡显示策略版本、事实/写作参考/偏好来源与检查范围；保留显式策略确认，修改优惠后必须重新测算和确认。
6. 本地进程重启和整套备份恢复已经独立验收；待补资料/待确认策略可接着完成，重复确认请求不会重复生成。本机启动的数据与图状态均隔离在指定runtime。

建议试用：上传仅含“品牌名称、商品名称、价格”的 TXT。先问“为什么需要这些信息”，再一次补充“品牌介绍：……；商品卖点：……”。核对并确认后，补充成本和销量数据，提出营销需求。刷新页面后应继续同一任务，不能自动将未确认资料写成事实。

## 对应实现

| 部分 | 职责 | 主要代码 |
|---|---|---|
| 前端 | 问题组、统一输入、编辑/确认、历史、来源说明 | `frontend/src/agent.js`、`agent-workspace.js` |
| 问题与意图 | 后端检查依赖/缺项，构造稳定问题ID；模型理解自然语言和目标变化 | `marketing_agent/questions.py`、`intake.py`、`model.py` |
| 编排 | 有界主Agent决策/工具循环；确定性成本规则；用户确认 | `marketing_agent/graph.py`、`business.py` |
| 等待恢复 | `prepare_wait → await_input → interrupt`；同任务 `Command(resume=...)` | `marketing_agent/runtime.py` |
| 事务投影 | revision、幂等request_id、审批、作品版本；上传/编辑同步图状态 | `marketing_agent/store.py`、`attachments.py` |
| 知识与记忆 | 原文件留存；确认后资料进入检索；用户确认的风格长期保存 | `knowledge.py`、`knowledge_index.py`、`studio.py` |
| 身份 | 后端会话定位工作区；查询/修改/后台线程沿用工作区 | `auth.py`、`workspace.py` |

这仍是一个主Agent加工具，不是多个拟人化子Agent。问题是否缺失、优惠是否可行、能否确认由后端规则把关；模型负责意图、字段理解、工具选择和表达。离线演示与真实模型模式在页面明确区分。

## SDD 是怎么落实的

当前增量有 `spec.md → plan.md/data-model.md → tasks.md → 验收测试 → 代码 → validation.md`。规格中 FR 编号对应测试和实现模块；JSON契约从运行时模型导出到 `docs/agent-contracts.json`，避免手写第二套规范。

这轮先增加批次、上传继承、意图与原生中断的失败验收，再逐步实现；发现真实模型漏提取多项条件后补充 FR-009、修复协议及回归测试。不能把“安装了Spec Kit目录”视为完成SDD，也不声称已有全工程自动审批/CI约束。

团队分工：PM维护用户故事/验收；Agent与前端组维护对话协议和恢复；经营分析组维护带单位、来源与版本的工具输入输出、计算边界和异常样例。修改共享字段须同步契约与用例，不在分析工具内另起聊天调度。
