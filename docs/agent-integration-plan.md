# 营销 Agent 本地整合计划

日期：2026-11-15。工作分支：`feat/agent-integration`。

## 目标与基线

以本地 `feat/marketing-agent`（main ec0c366 + shared-brand-workspace 610b669 及未提交的 Agent 实现）为基础，选择性吸收队友 `feature/agent-team@0dfe79c` 的对话附件、经营分析和方案比较思路。保留米白、棕橙配色。源码快照在项目外层 `artifacts/agent-before-integration-20261115.zip`；队友预览仍在 8022。

验收主线：选择品牌 → 上传/确认品牌资料与经营数据 → 对话补信息 → 查询经营情况 → 比较优惠策略 → 确认具体版本 → 生成文案 → 局部修改。

## 架构与分工

- 前端：聊天、品牌选择、附件草稿确认、分析与方案卡片；管理页面继续维护商品与资料。
- 主 Agent：LangGraph 理解意图、合并需求、选择工具、追问和解释。离线规则仅作为显式演示替身。
- 知识服务：复用现有上传、资料整理、确认、版本和品牌检索；不让未经确认的生成内容自动成为品牌事实。
- 经营工具：统一 JSON、金额整数分、日期左闭右开；显式区分示例数据、用户提供数据和情景假设。计算器用代码；不把销量相关性当因果，不伪造缺失成本或预计销量。
- 业务后端：会话持久化、版本校验、请求去重、确认门槛和知识/经营数据变更后的失效检查。
- 文案：读取确认策略与品牌事实，保留锁定条款；局部修改传入旧文案并由代码保留未选字段。

## 实施顺序

1. 数据与工具：接通品牌商品、导入单门店自提经营汇总 CSV，先预览再确认；缺失留空；统一分析与测算来源。
2. 品牌对话：会话绑定品牌，支持附件整理和确认；商品、知识、经营快照进入后续决策及版本依赖。
3. 策略提案：实时模型依据上下文提出2—3种受限优惠；离线提供第二杯半价、七折与原价候选。后端计算可行性与同销量情景比较；用户选择后再确认生成。未知销量追问；无基线不输出增量 ROI，历史均值基线仅作标注情景。
4. 内容闭环：品牌风格与事实进入文案；标题等局部修改保持其他字段不变；活动条件变化强制重新确认。

## 范围与边界

第一阶段限定单品牌、单门店、自提渠道、单活动和单平台文案。导入数据是用户提供，非平台自动核验。聚合销量只能支持情景测算，不能证明活动因果收益；不接入 CTR/CVR。图片/视频、语音、独立子 Agent、公网多租户和自动发布后置。没有有效模型配置时不得声称通过真实 LLM 验收。
